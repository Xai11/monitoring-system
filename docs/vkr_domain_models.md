# Доменные модели системы обнаружения аномалий

Система обнаружения аномалий оперирует двумя доменными моделями, каждая из которых
отражает одну смысловую единицу в потоке обработки данных: `SpanRecord` — единица
наблюдения, поступающая из телеметрии, и `AlertEvent` — единица вывода, передаваемая
в подсистему оповещения.

---

## Листинг доменных моделей

Листинг 1 — `SpanRecord.java` и `AlertEvent.java`

```java
package com.example.monitoring.streams;

public record SpanRecord(String serviceName, double durationMs, String traceId) {
    // Used as Kafka Streams intermediate value — serialized to JSON by JsonSerde
}
```

```java
package com.example.monitoring.alerting;

import com.fasterxml.jackson.annotation.JsonInclude;
import java.time.Instant;

@JsonInclude(JsonInclude.Include.NON_NULL)
public record AlertEvent(
    String service,
    String ruleType,   // THRESHOLD | RATE | ABSENCE
    double value,
    double threshold,
    String severity,   // warning | critical
    String summary,
    String traceId,    // exemplar trace for correlation
    Instant firedAt
) {}
```

---

## SpanRecord — промежуточное значение Kafka Streams

`SpanRecord` представляет один обработанный спан (span) трассировки OpenTelemetry,
десериализованный из топика Kafka и приведённый к минимально необходимому виду для
потоковой агрегации. Класс объявлен Java-записью (`record`), введённой в Java 16
как финальный неизменяемый носитель данных с автоматически синтезируемыми
конструктором, методами доступа, `equals`, `hashCode` и `toString`.

**Выбор `record` вместо `class`.** Потоковый процессор Kafka Streams создаёт и
уничтожает тысячи экземпляров промежуточных значений в секунду. Семантика
неизменяемости (`record` не имеет сеттеров и не допускает наследования) исключает
ситуацию, при которой один поток агрегации случайно мутирует объект, используемый
другим; это особенно важно при `num.stream.threads: 2` в конфигурации. Кроме того,
компактный синтаксис `record` служит явным документальным сигналом: данный класс
является чистым контейнером данных, а не объектом с поведением.

**Поля и их обоснование:**

- `serviceName` (`String`) — имя сервиса-источника спана, инжектируемое OTel-агентом
  через переменную окружения `OTEL_SERVICE_NAME`. Выступает ключом группировки в
  операции `groupBy` Kafka Streams: агрегация p99 ведётся независимо для каждого
  сервиса, что позволяет локализовать нарушение до конкретного микросервиса.

- `durationMs` (`double`) — длительность спана в миллисекундах, преобразованная из
  наносекундного формата OpenTelemetry. Тип `double` выбран для сохранения
  субмиллисекундной точности и совместимости с T-Digest API, принимающим `double`.
  Это единственная метрическая величина, необходимая для вычисления перцентилей;
  все прочие атрибуты спана (теги, события, статус) отбрасываются на этапе
  десериализации, сокращая объём данных, хранящихся в state store Kafka Streams.

- `traceId` (`String`) — шестнадцатеричный идентификатор трассировки W3C TraceContext
  (32 символа). Поле передаётся без изменений в `AlertEvent.traceId` и используется
  как *exemplar* — прямая ссылка на конкретный трейс в Jaeger, который был в памяти
  T-Digest в момент, когда p99 превысил порог. Наличие `traceId` в промежуточной
  модели — ключевое архитектурное решение: без него оповещение содержало бы только
  статистику (число, порог), но не давало бы отправной точки для расследования.

## AlertEvent — событие оповещения

`AlertEvent` — итоговый артефакт детектора, публикуемый в топик `otel.alerts.pending`
и пересылаемый в Alertmanager. Аннотация `@JsonInclude(NON_NULL)` обеспечивает
компактную сериализацию: поля, не заполненные для конкретного типа правила (например,
`traceId` для правила ABSENCE), не попадают в JSON-сообщение, что предотвращает
ложную интерпретацию `null` как осмысленного значения на стороне получателя.

**Поля и их назначение:**

- `service` (`String`) — имя сервиса-нарушителя, скопированное из `SpanRecord.serviceName`
  или из метки Prometheus. Используется Alertmanager для маршрутизации: оповещения
  одного сервиса могут направляться в отдельный канал Slack или на конкретного
  дежурного (on-call).

- `ruleType` (`String`) — тип сработавшего правила: `THRESHOLD` (абсолютное пороговое
  значение), `RATE` (превышение частоты событий), `ABSENCE` (отсутствие сигнала в
  течение ожидаемого интервала). Поле обеспечивает расширяемость: новый тип правила
  добавляется как новый обработчик `RuleHandler` и регистрирует собственную строку
  в `ruleType`, не изменяя ни схему события, ни код маршрутизации.

- `value` (`double`) — фактическое значение метрики в момент срабатывания (например,
  вычисленный p99 в мс или текущая доля DLQ-сообщений). Передаётся в тело
  оповещения Alertmanager, откуда попадает в шаблон Slack-сообщения, позволяя
  дежурному сразу видеть масштаб отклонения без открытия Grafana.

- `threshold` (`double`) — сконфигурированный порог из `MonitoringProperties`,
  действовавший в момент срабатывания. Фиксация порога непосредственно в событии
  важна для аудита: если порог был изменён после инцидента, история алертов в
  Alertmanager по-прежнему содержит значение, которое реально использовалось.

- `severity` (`String`) — уровень серьёзности (`warning` или `critical`), по которому
  Alertmanager выбирает маршрут доставки и время ожидания перед повторной
  отправкой (repeat_interval). Присваивается детектором в зависимости от
  величины превышения порога или типа правила.

- `summary` (`String`) — человекочитаемое описание инцидента, формируемое детектором
  (пример: `"p99 latency 312 ms > 200 ms threshold for order-service"`). Служит
  заголовком Slack-оповещения и записью в журнале Alertmanager, не требуя
  раскодирования числовых полей.

- `traceId` (`String`, **exemplar**) — идентификатор трассировки из `SpanRecord`,
  хранившегося в T-Digest в момент превышения порога. Это поле реализует концепцию
  *exemplar*: оно связывает агрегированный статистический сигнал (p99 > 200 мс)
  с конкретным распределённым трейсом в Jaeger. Дежурный, получив оповещение, может
  перейти непосредственно по ссылке `http://jaeger:16686/trace/{traceId}` и увидеть
  всю цепочку спанов, вызвавшую аномалию. Поле помечено `@JsonInclude(NON_NULL)`,
  поэтому для правил RATE и ABSENCE, где отдельный трейс-виновник неприменим,
  оно отсутствует в JSON без дополнительной логики ветвления.

- `firedAt` (`Instant`) — временна́я метка момента срабатывания правила в UTC. Поле
  выполняет две функции. Первая — хронологическая: Alertmanager и Grafana используют
  его для упорядочивания событий на временно́й шкале и вычисления интервала между
  срабатываниями (для дедупликации и подавления повторных оповещений). Вторая —
  управление жизненным циклом (TTL): если `monitoring-service` перестаёт публиковать
  обновлённые события для данного алерта, Alertmanager переводит его в состояние
  `resolved` по истечении `resolve_timeout`, исчисляемого от последнего `firedAt`.
  Тип `Instant` (а не `String` или `long`) обеспечивает независимость от временно́й
  зоны и прямую совместимость с ISO 8601-сериализацией Jackson.
